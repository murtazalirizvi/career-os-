# Requirements Document: Feature 3 Skill Arbitrage Hardening

## Introduction

This document specifies the requirements for Feature 3 Skill Arbitrage Hardening enhancements. These improvements enhance the existing Skill Arbitrage system with six specific capabilities: AI learning path persistence, composite full-run endpoint, Gemini-powered market commentary, salary currency field, market snapshot caching, and trending skills endpoint. The enhancements build upon the existing Feature 3 system which already provides market analysis, gap detection, skill sprint planning, and ROI reporting.

## Glossary

- **Feature3_Engine**: The existing skill gap analysis engine that processes market data and generates recommendations
- **Market_Snapshot**: A stored market analysis result with job counts, salary data, and skill requirements
- **Gap_Snapshot**: Analysis comparing candidate's current skills against market requirements
- **Skill_Sprint**: A focused learning plan for acquiring a specific skill
- **ROI_Report**: Return on investment analysis for skill acquisition
- **Gemini_Client**: The AI service integration for natural language market commentary and learning paths
- **AI_Learning_Path**: Structured learning roadmap generated by Gemini to address skill gaps
- **Market_Commentary**: Natural language narrative explaining market trends and opportunities
- **Salary_Currency**: Currency denomination for salary data (USD/PKR/GBP)
- **Market_Cache**: In-memory cache for market snapshots to reduce API calls
- **Trending_Skills**: Top rising skills across recent market snapshots

## Requirements

### Requirement 1: AI Learning Path Persistence

**User Story:** As a job seeker, I want my Gemini-generated learning path saved to the database, so that I can retrieve it later without re-running the AI analysis.

#### Acceptance Criteria

1. WHEN the Feature3_Engine completes gap analysis, THE system SHALL persist AI learning path to the ai_learning_path_json column
2. THE Gap_Snapshot SHALL store AI learning path as JSON containing structured learning recommendations
3. WHEN retrieving a gap snapshot, THE system SHALL include the persisted AI learning path in the response
4. WHEN Gemini is unavailable during analysis, THE system SHALL store an empty JSON object in ai_learning_path_json
5. THE ai_learning_path field SHALL be populated for all new gap snapshots without breaking existing functionality
6. WHEN AI learning path is empty, THE system SHALL return an empty dictionary in the API response

### Requirement 2: Composite Full-Run Endpoint

**User Story:** As a job seeker, I want a single endpoint that runs all four analyses (market → gap → sprint → ROI), so that I don't need to make four separate API calls.

#### Acceptance Criteria

1. THE system SHALL provide a POST /api/feature3/full-run endpoint
2. WHEN calling full-run, THE system SHALL execute market analysis, gap analysis, sprint planning, and ROI calculation in sequence
3. THE full-run endpoint SHALL accept all parameters needed for the four analyses
4. THE full-run endpoint SHALL return a composite response containing all four analysis results
5. WHEN any step fails, THE system SHALL return a descriptive error indicating which step failed
6. THE full-run endpoint SHALL create database records for all four analyses
7. THE full-run endpoint SHALL complete within 30 seconds for typical inputs

### Requirement 3: Gemini-Powered Market Commentary

**User Story:** As a job seeker, I want natural language market insights, so that I can understand market trends without interpreting raw job counts.

#### Acceptance Criteria

1. THE Market_Snapshot SHALL include a market_commentary field with natural language insights
2. WHEN generating market commentary, THE system SHALL use Gemini to analyze job counts, salary ranges, and skill requirements
3. THE market commentary SHALL be 3-5 sentences explaining market trends, demand patterns, and opportunities
4. WHEN Gemini is unavailable, THE system SHALL generate a basic commentary from heuristics
5. THE market commentary SHALL mention specific numbers (job counts, salary ranges) from the analysis
6. THE market commentary SHALL be stored in the market_commentary_json field in the database

### Requirement 4: Salary Currency Field

**User Story:** As a job seeker in different regions, I want salary data in my local currency, so that I can make informed decisions about market opportunities.

#### Acceptance Criteria

1. THE Market_Snapshot SHALL include a salary_currency field with allowed values: "USD", "PKR", "GBP"
2. THE market analysis endpoint SHALL accept an optional salary_currency parameter
3. WHEN salary_currency is not provided, THE system SHALL default to "USD"
4. WHEN salary_currency is "PKR", THE system SHALL convert USD salaries to PKR using current exchange rate
5. WHEN salary_currency is "GBP", THE system SHALL convert USD salaries to GBP using current exchange rate
6. THE market snapshot response SHALL include salary_currency in the response
7. THE salary_currency field SHALL be indexed for filtering market snapshots by currency

### Requirement 5: Market Snapshot Caching

**User Story:** As a system administrator, I want market snapshots cached for 6 hours, so that repeated queries don't hit expensive external APIs.

#### Acceptance Criteria

1. THE system SHALL cache market snapshots by (target_role, region) key for 6 hours
2. WHEN a cached snapshot exists and is less than 6 hours old, THE system SHALL return the cached data
3. WHEN a cached snapshot is older than 6 hours, THE system SHALL fetch fresh data and update the cache
4. THE cache SHALL be in-memory using an LRU strategy with maximum 50 entries
5. THE cache SHALL be thread-safe for concurrent requests
6. THE system SHALL log cache hits and misses for monitoring
7. WHEN cache is full, THE system SHALL evict the least recently used entry

### Requirement 6: Trending Skills Endpoint

**User Story:** As a job seeker, I want to see which skills are rising in demand, so that I can prioritize learning high-growth skills.

#### Acceptance Criteria

1. THE system SHALL provide a GET /api/feature3/trending-skills endpoint
2. THE trending skills endpoint SHALL return the top 10 rising skills across all recent market snapshots
3. THE trending skills SHALL be calculated from market snapshots created in the last 30 days
4. EACH trending skill SHALL include: skill name, job count, growth percentage, and average salary
5. THE trending skills SHALL be ordered by growth percentage (highest first)
6. WHEN no market snapshots exist in the last 30 days, THE system SHALL return an empty list
7. THE trending skills endpoint SHALL complete within 5 seconds

### Requirement 7: Database Migration for New Fields

**User Story:** As a database administrator, I want a migration script for new fields, so that existing data remains intact while adding new capabilities.

#### Acceptance Criteria

1. THE system SHALL provide a migration script that adds salary_currency and market_commentary_json columns to the Feature3MarketSnapshot table
2. WHEN running the migration, THE system SHALL set salary_currency to "USD" for existing records
3. WHEN running the migration, THE system SHALL set market_commentary_json to "{}" for existing records
4. THE migration SHALL add database indexes on salary_currency field
5. THE migration SHALL be idempotent and safe to run multiple times
6. WHEN the migration completes, THE system SHALL verify that all existing records have non-null values for new fields

### Requirement 8: Error Handling and Backward Compatibility

**User Story:** As a system administrator, I want robust error handling and backward compatibility, so that existing clients continue to work while new features are adopted gradually.

#### Acceptance Criteria

1. WHEN Gemini API calls fail during market commentary or learning path generation, THE system SHALL return HTTP 502 with descriptive error messages
2. THE existing individual endpoints (market, gap, sprint, ROI) SHALL continue to work independently
3. WHEN salary_currency is omitted from requests, THE system SHALL use "USD" as default
4. THE system SHALL log all Gemini failures and cache operations for monitoring
5. WHEN retrieving old market snapshots without market_commentary_json, THE system SHALL return an empty string
6. WHEN retrieving old gap snapshots without ai_learning_path_json, THE system SHALL return an empty dictionary
7. THE API SHALL maintain the same response format for existing endpoints while adding new optional fields

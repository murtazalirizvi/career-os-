# Requirements Document

## Introduction

This document specifies the requirements for Feature 2 Interview Rebound Hardening enhancements. These improvements enhance the existing Interview Rebound system with six specific capabilities: AI insights persistence, AI regeneration endpoint, practice drill generation, webhook-based transcription, interview date tracking, and company stage context. The enhancements build upon the existing Feature 2 system which already provides interview autopsy with technical, behavioral, and strategic analysis, AssemblyAI transcription integration, Gemini AI coaching, and comprehensive scoring and trend analysis.

## Glossary

- **Feature2_Engine**: The existing interview analysis engine that processes transcripts and generates autopsy reports
- **Autopsy_Record**: A stored interview analysis result with scores, insights, and strategic actions
- **Gemini_Client**: The AI service integration for natural language coaching and practice drill generation
- **AI_Insights**: Structured coaching response with diagnosis, perfect answer, week plan, and mindset sections
- **AssemblyAI_Service**: External transcription service that converts audio to text
- **Webhook_Handler**: Component that receives and processes asynchronous transcription completion notifications
- **Practice_Drill**: A set of 3 targeted questions generated by Gemini to address the weakest area from an autopsy
- **Interview_Date**: The actual date when the interview occurred (distinct from record creation date)
- **Company_Stage**: Classification of company size and maturity (startup/scaleup/enterprise)
- **Polling_Loop**: Current synchronous transcription approach that blocks the request thread

## Requirements

### Requirement 1: AI Insights Persistence

**User Story:** As a job seeker, I want my Gemini coaching insights saved to the database, so that I can retrieve them later without re-running the AI analysis.

#### Acceptance Criteria

1. WHEN the Feature2_Engine completes interview analysis, THE system SHALL persist AI insights to the ai_insights_json column
2. THE Autopsy_Record SHALL store AI insights as JSON containing diagnosis, perfect_answer, week_plan, and mindset sections
3. WHEN retrieving an interview autopsy, THE system SHALL include the persisted AI insights in the response
4. WHEN Gemini is unavailable during analysis, THE system SHALL store an empty JSON object in ai_insights_json
5. THE ai_insights field SHALL be populated for all new interview autopsies without breaking existing functionality
6. WHEN AI insights are empty, THE system SHALL return an empty dictionary in the API response

### Requirement 2: AI Regeneration Endpoint

**User Story:** As a job seeker, I want to re-run Gemini coaching on an existing interview, so that I can get fresh insights without re-submitting the full interview data.

#### Acceptance Criteria

1. THE system SHALL provide a POST /api/feature2/interviews/{id}/regenerate-ai endpoint
2. WHEN regenerating AI insights, THE system SHALL retrieve the existing autopsy record from the database
3. THE system SHALL call the Gemini_Client with the stored interview data and analysis results
4. WHEN regeneration succeeds, THE system SHALL update the ai_insights_json column with new insights
5. WHEN the interview ID does not exist, THE system SHALL return HTTP 404 with a descriptive error message
6. WHEN Gemini is unavailable, THE system SHALL return HTTP 502 with an appropriate error message
7. THE regeneration endpoint SHALL return the updated autopsy record with new AI insights

### Requirement 3: Practice Drill Generation

**User Story:** As a job seeker, I want targeted practice questions for my weakest area, so that I can improve specific skills identified in my interview autopsy.

#### Acceptance Criteria

1. THE system SHALL provide a POST /api/feature2/interviews/{id}/practice-drill endpoint
2. WHEN generating a practice drill, THE system SHALL identify the weakest scoring dimension from the autopsy
3. THE Practice_Drill SHALL contain exactly 3 questions targeting the identified weakness
4. WHEN the weakest area is technical, THE Gemini_Client SHALL generate questions focused on technical depth and accuracy
5. WHEN the weakest area is behavioral, THE Gemini_Client SHALL generate STAR-format scenario questions
6. WHEN the weakest area is strategic recovery, THE Gemini_Client SHALL generate questions about follow-up and negotiation
7. THE practice drill response SHALL include the weakness category, score, and the 3 generated questions
8. WHEN the interview ID does not exist, THE system SHALL return HTTP 404 with a descriptive error message
9. WHEN Gemini is unavailable, THE system SHALL return HTTP 502 with an appropriate error message

### Requirement 4: AssemblyAI Webhook Support

**User Story:** As a system administrator, I want webhook-based transcription, so that long audio files don't block request threads and cause timeouts.

#### Acceptance Criteria

1. THE system SHALL provide a POST /api/feature2/webhooks/assemblyai endpoint to receive transcription completion notifications
2. WHEN submitting audio for transcription, THE system SHALL register a webhook URL with AssemblyAI
3. THE system SHALL create an Autopsy_Record with status "transcribing" immediately after submitting audio
4. WHEN the Webhook_Handler receives a completion notification, THE system SHALL retrieve the transcript from AssemblyAI
5. WHEN transcription completes successfully, THE system SHALL update the Autopsy_Record with the transcript and run the full analysis
6. WHEN transcription fails, THE system SHALL update the Autopsy_Record status to "transcription_failed" with error details
7. THE webhook endpoint SHALL validate the AssemblyAI signature to prevent unauthorized requests
8. THE system SHALL maintain backward compatibility with the existing polling-based transcription for clients that don't use webhooks
9. WHEN using webhook mode, THE system SHALL return the interview ID immediately without waiting for transcription

### Requirement 5: Interview Date Field

**User Story:** As a job seeker, I want to record when my interview actually happened, so that I can filter and sort my interview history by actual interview date rather than submission date.

#### Acceptance Criteria

1. THE Autopsy_Record SHALL include an interview_date field that stores the actual interview date
2. THE interview creation endpoint SHALL accept an optional interview_date parameter in ISO 8601 format
3. WHEN interview_date is not provided, THE system SHALL default to the current date
4. THE interview retrieval endpoints SHALL include interview_date in the response
5. THE candidate trend endpoint SHALL support ordering by interview_date instead of created_at
6. WHEN filtering interviews, THE system SHALL allow date range queries on interview_date
7. THE interview_date field SHALL be indexed for efficient querying and sorting

### Requirement 6: Company Stage Field

**User Story:** As a job seeker, I want to specify the company stage, so that culture and vibe scoring is more accurate based on company context.

#### Acceptance Criteria

1. THE Autopsy_Record SHALL include a company_stage field with allowed values: "startup", "scaleup", "enterprise"
2. THE interview creation endpoint SHALL accept an optional company_stage parameter
3. WHEN company_stage is not provided, THE system SHALL default to "scaleup"
4. WHEN calculating culture vibe scores, THE Feature2_Engine SHALL adjust scoring based on company_stage
5. WHEN company_stage is "startup", THE system SHALL increase tolerance for informal culture by 10 points
6. WHEN company_stage is "enterprise", THE system SHALL increase expectations for structured process by 10 points
7. THE interview retrieval endpoints SHALL include company_stage in the response
8. THE company_stage field SHALL be indexed for filtering interviews by company type

### Requirement 7: Webhook Security and Validation

**User Story:** As a security engineer, I want webhook requests validated, so that only legitimate AssemblyAI notifications are processed.

#### Acceptance Criteria

1. WHEN receiving webhook requests, THE Webhook_Handler SHALL verify the request signature using the AssemblyAI secret
2. WHEN signature verification fails, THE system SHALL return HTTP 401 and reject the request
3. THE system SHALL validate that the transcript ID in the webhook matches an existing pending autopsy record
4. WHEN the transcript ID is not found, THE system SHALL log the event and return HTTP 404
5. THE webhook endpoint SHALL use HTTPS in production environments
6. THE system SHALL rate-limit webhook requests to prevent abuse (maximum 100 requests per minute per IP)
7. WHEN webhook processing fails, THE system SHALL return appropriate HTTP error codes without exposing internal details

### Requirement 8: Database Migration for New Fields

**User Story:** As a database administrator, I want a migration script for new fields, so that existing data remains intact while adding new capabilities.

#### Acceptance Criteria

1. THE system SHALL provide a migration script that adds interview_date and company_stage columns to the Feature2InterviewAutopsy table
2. WHEN running the migration, THE system SHALL set interview_date to created_at for existing records
3. WHEN running the migration, THE system SHALL set company_stage to "scaleup" for existing records
4. THE migration SHALL add database indexes on interview_date and company_stage fields
5. THE migration SHALL be idempotent and safe to run multiple times
6. WHEN the migration completes, THE system SHALL verify that all existing records have non-null values for new fields

### Requirement 9: Error Handling and Backward Compatibility

**User Story:** As a system administrator, I want robust error handling and backward compatibility, so that existing clients continue to work while new features are adopted gradually.

#### Acceptance Criteria

1. WHEN webhook transcription fails, THE system SHALL fall back to polling-based transcription for retry attempts
2. WHEN Gemini API calls fail during regeneration or practice drill generation, THE system SHALL return HTTP 502 with descriptive error messages
3. THE existing polling-based transcription flow SHALL continue to work for clients that don't provide webhook URLs
4. WHEN interview_date or company_stage are omitted from requests, THE system SHALL use sensible defaults
5. THE system SHALL log all webhook failures and AI service errors for monitoring
6. WHEN retrieving old autopsy records without ai_insights_json, THE system SHALL return an empty dictionary
7. THE API SHALL maintain the same response format for existing endpoints while adding new optional fields
